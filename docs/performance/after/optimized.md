## 2. DevTools Network Tab Testing Checklist

When running the application with `Disable cache` and `Slow 3G` in Chrome DevTools:

### Step-by-Step Verification Protocol
1. **Initial Page Load (`/`):**
   - The initial download fetches `index-CjdN3FIQ.js` and vendor chunks.
   - `Projects-*.js`, `Contact-*.js`, and `ActivityLogs-*.js` are **NOT** fetched.
2. **Navigate to `/projects`:**
   - DevTools Network JS filter captures an on-demand GET request for `Projects-Gs7ZY4vI.js` (6.24 kB).
   - The `<LoadingFallback />` component displays the animated luxury ring and "Loading page component..." message smoothly while the chunk streams in.
3. **Navigate to `/contact`:**
   - DevTools Network JS filter captures an on-demand GET request for `Contact-CzFNweA9.js` (5.12 kB).
   - The fallback renders smoothly, and once resolved, renders the contact form.
4. **Navigate to `/task` and click "Activity Logs":**
   - DevTools Network JS filter captures an on-demand GET request for `ActivityLogs-B02FnL-i.js` (2.19 kB).
   - Component-level Suspense fallback displays the spinning loading indicator inline.
5. **Back / Forward Cache Navigation:**
   - Once downloaded into browser memory, revisiting `/projects` or `/contact` resolves immediately without re-fetching from the network.
6. **Direct Deep Link Refresh (`/projects`, `/contact`):**
   - Refreshing directly on `/projects` triggers lazy chunk resolution seamlessly without 404 or blank screen errors.
